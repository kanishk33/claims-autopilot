# Data sources, licensing, and how each one is used

Retrieval date for everything below: **2026-10-23**. Re-check license terms before any non-educational use.

## 1. X12 code lists: CARC, RARC, Claim Adjustment Group Codes

- Pages: <https://x12.org/codes/claim-adjustment-reason-codes>, <https://x12.org/codes/remittance-advice-remark-codes>, <https://x12.org/codes/claim-adjustment-group-codes>
- Maintainers: CARCs by the Code Maintenance Committee; RARCs by CMS; distributed by X12.
- License: X12 states that *"All X12 work products are copyrighted"* and that use must comply with US copyright law and X12 intellectual-property policies (<https://x12.org/products/ip-use>). The lists can be viewed publicly. Bulk or commercial reuse goes through X12's code-list licensing (<https://ecommerce.x12.org/license/code-lists>).
- **How it is used here:** `data/carc_rarc_reference.csv` holds a **small subset (39 codes)** of official descriptions for educational, non-commercial demonstration, with a `source_url` and `retrieved_on` on every row. Two long descriptions are shortened and marked "(truncated; see source)".
  - The RARC N257 and N264 descriptions were taken from the Noridian Medicare (a CMS Medicare Administrative Contractor) denial-resolution page, <https://med.noridianmedicare.com/web/jfb/topics/claim-submission/denial-resolution>, because the X12 page could not be read in full by the retrieval tool.
- Columns `plain_language_project_note`, `suggested_actions_project_guidance`, and `typical_path` are **written by this project**. They are not official and are labeled as such.
- Limitation: codes outside the subset are reported as "not in local reference". The app never asks the LLM to define them.

## 2. CMS Place of Service code set

- Page: <https://www.cms.gov/medicare/coding-billing/place-of-service-codes/code-sets>
- Public CMS information. A subset of 12 common codes is in `data/validation_rules.yml`.

## 3. Code systems used in synthetic examples

- **ICD-10-CM** (diagnoses) is published by CDC/NCHS and CMS and is in the public domain. A handful of codes and descriptions appear in the synthetic data.
- **CPT** is copyrighted by the American Medical Association. This project uses CPT **code numbers only** as identifiers, with its **own short plain-English labels**. No AMA descriptors are included. HCPCS Level II codes (for example G0008) are CMS-maintained.

## 4. CMS Medicare Coverage Database (MCD), not bundled

- Page: <https://www.cms.gov/medicare-coverage-database/>
- Contents: National Coverage Determinations (NCDs), Local Coverage Determinations (LCDs), and billing and coding articles. CMS offers downloads. Content that includes CPT codes requires accepting the AMA license terms during download.
- **Planned use:** a retrieval source for medical-necessity denials (CARC 50/167). The copilot would retrieve the relevant LCD/NCD passage and cite it in the appeal draft. It is not bundled, because of the license acceptance step and the size of the database. (The automated fetch of the page failed during research, so this summary is based on CMS's published description of the database. Verify it before relying on it.)

## 5. CMS Medicare Claims Synthetic Public Use Files (DE-SynPUF), not bundled

- Page: <https://www.cms.gov/data-research/statistics-trends-and-reports/medicare-claims-synthetic-public-use-files>
- Contents: synthetic Medicare claims for 2008–2010, in the same structure as CMS Limited Data Sets. Free to download, subject to the CMS Data Disclaimer/User Agreement for public use data. CMS warns the files have *very limited inferential research value*.
- **Planned use:** SQL analytics practice at volume (claim and procedure distributions). Note that 2008–2010 claims use **ICD-9**, not ICD-10, so they cannot test this project's ICD-10 validation.

## 6. Project-generated synthetic data

- `data/synthetic_claims/` (28 claims) and `data/synthetic_denials/` (10 denials) are generated by `scripts/generate_synthetic_data.py` with **no randomness**, so they are reproducible. Patients are "SYNTHETIC PATIENT X", and payers and clinics are invented. NPIs are computed numbers that pass the NPI check digit; they were not checked against NPPES and are not intended to belong to anyone.
- `data/denial_knowledge_base.md` contains general revenue-cycle guidance written for this project. It is not payer policy.

## Training and fine-tuning

None. No model was trained or fine-tuned on any of these sources. The app retrieves local passages at run time (RAG) and passes them to the model with instructions to use only that context.
